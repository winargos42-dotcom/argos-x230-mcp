# Создание Cloudflare Tunnel через браузер

Этот мастер специально сделан так, чтобы человек не работал с секретными API-токенами и конфигами вручную.

## 1. Подготовка

Нужны: установленный `cloudflared`, собственный аккаунт Cloudflare, управляемый домен, браузер с возможностью войти в аккаунт Cloudflare. Установите MCP локально, проверьте HTTP 401 без токена.

```bash
.venv/bin/argos-mcp-tunnel-wizard
.venv/bin/argos-mcp-install-desktop  # необязательный ярлык
```

Откроется локальная страница наподобие `http://127.0.0.1:49152/`. **Не открывайте её во внешней сети. Повторный запуск мастера блокируется; по завершении нажмите кнопку «Закрыть мастер», чтобы освободить память.** Если браузер не запускается автоматически, укажите `--no-browser` и откройте выведенный локальный адрес самостоятельно.

## 2. Авторизация через браузер

Нажмите «Открыть вход через Cloudflare». Мастер вызывает официальную команду `cloudflared tunnel login`; в соседней вкладке откроется страница подтверждения владельца домена. По окончании в `~/.cloudflared/cert.pem` появится локальный сертификат для CLI.

Сертификат остаётся на вашем устройстве и **никогда не публикуется в GitHub**, ChatGPT, тикеты или лог MCP. Мастер не обходится без вашего подтверждения и не сохраняет пароль/2FA.

## 3. Создание и проверка

Введите имя (например, `argos-mcp`) и нажмите «Создать named tunnel». Мастер создаст уникальный Cloudflare Tunnel и сохранит ID только в текущем локальном сеансе. Старые туннели не затрагиваются.

Введите принадлежащий вам hostname (например, `mcp.example.com`), нажмите «Подготовить приватный конфиг». В домашней папке появится файл `~/.config/argos-x230-mcp/tunnels/argos-mcp.yml`, содержащий только новый туннель, локальный `127.0.0.1:8765` и catch-all 404.

## 4. Безопасный публичный доступ

Откройте в браузере Cloudflare Zero Trust → Access → Applications → Add application → Self-hosted. Укажите созданный hostname и политику доступа по своей учётной записи с обязательной авторизацией. Опубликуйте политику **до DNS**.

Вернувшись в мастер, отметьте подтверждение и нажмите «Создать DNS запись». Он добавит CNAME к новому туннелю **без перезаписи существующей DNS-записи**.

Затем нажмите «Проверить Access без авторизации». Мастер отправит анонимный HTTPS-запрос к вашему адресу и убедится, что сервер отвечает **редиректом на страницу входа Cloudflare Access**, а не просто статусом HTTP 401 от MCP или открытым ответом 200. Отсутствие такой проверки блокирует автоматическое включение нового туннеля.

## 5. Запуск только после подтверждения

После PASS проверки Access нажмите «Запустить новый туннель». Мастер ещё раз проверяет challenge и создаёт отдельную `systemd --user` службу с ограничением памяти и CPU. Она не изменяет `/etc/cloudflared/config.yml` и не перезапускает Home Assistant.

**Это не заменяет настройку самого MCP.** Добавьте `ARGOS_MCP_PUBLIC_HOSTNAME` и параметры `ARGOS_CF_ACCESS_TEAM/AUD/EMAIL` в закрытое окружение MCP, как показано в [INSTALL_RU.md](INSTALL_RU.md). Иначе клиент с JWT Cloudflare Access не пройдёт аутентификацию MCP.

## 6. Если что-то пошло не так

- Отсутствует сертификат: повторно авторизуйте Cloudflare через браузер. Не копируйте сертификат с чужого компьютера.
- DNS-запись существует: мастер не перезапишет её. Проверьте в Cloudflare Dashboard и выберите другой hostname.
- Проверка Access не пройдена: исправьте политику и повторите. Туннель не будет запущен мастером.
- X230 перегружен: не открывайте новый Chromium; дождитесь освобождения памяти.
- После создания нового service: `systemctl --user status argos-x230-mcp-tunnel-ИМЯ.service`.
- Остановить: `systemctl --user disable --now argos-x230-mcp-tunnel-ИМЯ.service`. DNS нужно удалять отдельно в Cloudflare, если больше не нужен.

## Безопасность

Мастер работает только на 127.0.0.1, использует случайный CSRF-токен и проверяет Origin/Host запросов. Никакого root/sudo, произвольных shell-команд и автоматического изменения существующих туннелей. Облачные действия требуют отдельного нажатия, а авторизация в браузере остаётся у владельца.
