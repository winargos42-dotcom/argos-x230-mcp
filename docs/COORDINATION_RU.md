# ARGOS: постоянная координация агентов (без новых зависимостей)

**Назначение:** дать существующему файловому agent-bridge на X230 надёжный
журнал заданий и подлинных подтверждений. Не запускать новый стек агентов,
не изменять Core, RootGuard, кошельки или существующие рабочие процессы.

## Модель достоверности

- QUEUED: задача записана в SQLite, но агент **не получил** её.
- ACKED: агент предъявил HMAC-доказательство для конкретного task_id и SHA задания.
- RUNNING: тот же агент подтвердил начало работы.
- DONE_REPORTED: агент сообщил результат и SHA артефакта, но артефакт
  ещё **не проверен**.
- VERIFIED: координатор самостоятельно перечитал локальный файл
  из защищённого workspace и подтвердил SHA-256.
- FAILED: агент сообщил ошибку; NEEDS_OWNER: у задачи закончилась аренда,
  и её нельзя безопасно запускать повторно.

Сообщения старого agent-bridge (inbox_argos/archive) импортируются только
как LEGACY_OBSERVED_UNVERIFIED. Обычный JSON answer с task=None,
ошибкой или пустым текстом **никогда** не становится ACK или DONE.

SQLite WAL + synchronous=FULL хранит очередь между перезапусками. Для
обработки внутри одного процесса допустим asyncio.Queue как уведомление;
он **не** источник истины и не заменяет подтверждение другого агента.

## Где хранится состояние

В уже существующем каталоге ARGOS MCP workspace:

- agent-bridge/coordination.sqlite3 — SQLite с задачами и событиями.
- agent-bridge/.agents.json — закрытая карта agent_name → 32-байтный
  шестнадцатеричный секрет (права 0600). **Никогда не коммитить.**
- Исходные inbox_hermes/inbox_argos/archive **не переписываются**.

Все изменения в файловой системе — в пределах workspace текущего
непривилегированного пользователя MCP. Модуль не вызывает ни shell,
ни RootGuard, ни сторонние API; старые инструменты сервера сохраняются.

Пример **структуры**, без настоящих ключей:

    {
      "opencode": "<случайные 64 hex символа>",
      "zcode": "<отдельные 64 hex символа>"
    }

Ключи создаются и безопасно доставляются владельцем отдельно, в разрешённых
средствах ОС. Нельзя передавать их через ChatGPT или журналы.
Если файла ключей нет либо права шире 0600, операции ACK/POLL блокируются.

## MCP-интерфейс

1. Координатор вызывает coordination_submit(task_id, recipient, instruction,
   source_ref, retry_safe). При повторе с тем же ID и тем же содержимым
   не создаётся вторая задача; несовпадающий повтор отвергается.
2. Уже работающий агент (без создания нового процесса) запрашивает
   coordination_poll(agent, proof). Для proof вычисляет:
   HMAC_SHA256(agent_key, UTF8("poll\n" + agent)).
3. Агент даёт coordination_agent_event(task_id, "ack", proof), затем
   "start". Подпись для ack или start:
   HMAC_SHA256(agent_key, UTF8(action + "\n" + task_id + "\n" + payload_sha)).
4. При выполнении агент помещает артефакт в доступный координатору каталог
   workspace, вычисляет SHA-256 и вызывает
   coordination_agent_event(task_id, "complete", proof, result=...,
   artifact_sha=..., artifact_path=...). Подпись строится по
   UTF8("complete\n" + task_id + "\n" + payload_sha + "\n" +
   sha256(UTF8(result)) + "\n" + artifact_sha + "\n" + artifact_path).
   При ошибке fail подписывает "fail\n" + task_id + "\n" + payload_sha +
   "\n" + sha256(UTF8(result)).
5. Dot (единый интегратор) или координатор проверяет
   coordination_verify(task_id). Только этот этап ставит VERIFIED.
6. coordination_status/coordination_list читают журнал. coordination_reconcile_expired
   возвращает в QUEUED **только** ранее помеченные retry_safe задачи
   с менее чем 3 попытками. Остальные переводит в NEEDS_OWNER.
7. coordination_observe_legacy(relative_path) принимает один уже
   существующий ответ из agent-bridge/inbox_argos либо archive и заносит его
   хеш в журнал, **не** меняя статус задачи.

Синхронизация X230 ↔ Coral осуществляется **существующим разрешённым**
MCP/SSH/файловым транспортом. Наличие этих функций в исходниках ещё не
доказывает, что удалённые OpenCode/ZCode действительно подключены или
получают задания.

## Обязательная приёмка

    python -m compileall -q src
    python -m unittest discover -s tests -v

Тесты проверяют повторную отправку, ошибочную подпись, роль агента,
переходы, восстановление после перезапуска, безопасный повтор,
SHA артефакта, отказ от обхода пути и импорт устаревшего пустого ответа.

**Перед применением на X230:** сравнить исходники с установленной версией,
выполнить резервную копию каталога agent-bridge, отдельно утвердить
развёртывание через RootGuard и только затем зарегистрировать MCP
инструменты в работающей службе. Заменять сервер, запускать новый
туннель или перезапускать Core здесь **не требуется**. Эта ветка не
изменяет работающий X230 до осознанного развёртывания.

**Конечная готовность ZomATON** требует независимого E2E подтверждения:
получение агентами заданий → фактический артефакт → SHA/тесты →
интеграция Dot → проверка покупательского пути. Очередь сама по себе
не означает, что NFT mint/ownership проверены.
