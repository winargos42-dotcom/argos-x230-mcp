# Security policy / Модель безопасности

## Общая модель доверия

Не доверяйте текстам промптов, файлам, содержимому Git-репозиториев и результатам тестируемого кода. Считайте MCP-клиент потенциально ошибающимся. Серверу необходимы отдельный непривилегированный Linux-пользователь, приватный workspace и проверка личности на границе сети.

MCP **не должен запускаться от root** и не предоставляет произвольный shell.

### Границы доступа

- Доступ к файлам — исключительно выделенный workspace с проверкой относительного пути после разрешения символических ссылок.
- Максимум 256 КБ для текстовых файлов; точечное изменение требует уникального совпадения.
- `run_safe_command` принимает строго перечисленные действия и никогда не интерпретирует произвольную команду.
- Git ограничен отдельным проектом: без remotes/push/pull, без shell и сетевых протоколов, без вызова hooks.
- Python unittest выполняется в bubblewrap, без сети, без домашнего каталога, с ограничениями CPU, RAM, времени и вывода; при нехватке ресурсов запуск откладывается.
- Показ статуса служб разрешён только для ограниченного списка, запись команд `systemctl start/stop/restart` отсутствует.
- Сбор audit-метаданных не включает содержимое исходников, токены и пароли.
- Токен локального сервера должен храниться вне Git (`chmod 600`) и передаваться только через доверенный канал.
- Публичный Cloudflare URL защищается Cloudflare Access и проверкой JWT (issuer, signature, audience, email) на стороне MCP. Без конфигурации Access-JWT запрос с JWT не проходит.

### Туннель-мастер

Локальный HTTP UI слушает только loopback. Формы защищены CSRF, Origin и Host. Обязателен реальный браузерный login Cloudflare; пароли и 2FA не автоматизируются. Создаётся **только новый** named tunnel. DNS не перезаписывается. Для автоматического запуска отдельного user-service требуется успешная проверка Access login challenge.

Отдельная cloudflared-подписка/тариф и DNS-зона относятся к пользователю, не к ARGOS.

### Ограничения / известные риски

- Обычный Linux-процесс, находящийся в workspace, может получить доступ ко всему, что разрешено самому пользователю MCP. Поэтому отдельный UID и системная песочница нужны в production.
- `resource_status` — предиктивная проверка, а не жёсткая RAM-квота; для новых исполнителей используйте cgroups + RLIMIT.
- Нельзя обещать полную защиту от 0-day, symlink race, уязвимостей ядра, загрузки зависимости из PyPI.
- Доступ по внешнему URL без рабочей Cloudflare Access политики небезопасен даже при отдельном локальном bearer токене: не открывайте такой URL.
- Не сохраняйте Cloudflare cert.pem, туннельные JSON credentials, `access.env`, Bearer-токены и приватные логи в репозитории.
- Команды read-only systemd logs могут вернуть содержимое журналов, доступных UID MCP; не расширяйте список для чувствительных служб.
- Если `bubblewrap` недоступен, тест должен завершаться отказом, а не выполнением тестов без песочницы.

## Сообщить об уязвимости

Пожалуйста, не публикуйте рабочий эксплойт или секреты в публичной GitHub issue. Используйте приватное сообщение владельцу репозитория через GitHub security reporting, если он включён. До исправления отзовите скомпрометированный ключ и отключите публичный маршрут.
